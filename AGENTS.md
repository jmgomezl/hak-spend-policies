# Repository Guidelines

## Project Structure
- `src/index.ts` is the package entry point; `src/spend-policies.ts` builds the full policy set from one config.
- `src/policies/` holds one file per policy. All extend `SpendPolicy` (`src/policies/base.ts`), which extends the Agent Kit's `AbstractPolicy`.
- `src/approval/scheduled-approval.ts` turns a refused payment into an owner-approval Scheduled Transaction.
- `src/extract.ts` maps each core tool's normalised params to outflows (`SpendItem[]`); `src/ledger.ts` tracks daily spend.
- `src/tools/` holds the two read-only plugin tools.
- `tests/` holds Vitest suites; `scripts/` holds the testnet integration test and the owner's `approve` script.
- `dist/` is generated by `tsup`; do not edit by hand.

## Commands
- `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`: the CI gate, in that order.
- `npm run test:integration` needs `HEDERA_ACCOUNT_ID` and `HEDERA_PRIVATE_KEY` for a funded testnet account, and a fresh `npm run build`.

## Conventions
- Biome: two-space indent, double quotes, 100-character lines. Run `npm run format` before committing.
- Policies refuse by throwing `SpendPolicyViolation`, never by returning `true`, so the model gets a specific reason.
- Amounts are `bigint` base units internally. Caps are display units in config and converted once, on the decimal string.
- Tool `method` names are snake_case and prefixed `spend_`; Zod fields carry `.describe()`.

## Testing
- Unit tests must not touch the network. Run real core tools in `RETURN_BYTES` mode through `tests/helpers.ts`, with the fake mirror node.
- Any safety property (the agent cannot approve its own payment, parallel calls cannot share budget, uncapped assets cannot move) belongs in a test, not only in prose.

## Security
- Private keys never cross a tool boundary. The approval step depends on the owner's key never being available to the agent.
